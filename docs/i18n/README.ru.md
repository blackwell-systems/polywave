**Параллельные AI-агенты, которые не ломают код друг друга, прямо в том CLI, которым вы уже пользуетесь.**

Polywave — это лёгкая надстройка, а не платформа для агентов. Вы продолжаете работать в Claude Code (или Codex). Установите один раз, и весь ваш интерфейс — это `/polywave` в том инструменте, которым вы уже пользуетесь: каждый агент получает собственный worktree, каждый файл закреплён ровно за одним агентом, и вы видите полный план до того, как хоть один агент коснётся вашего кода. Конфликты разрешаются на этапе планирования, а не на этапе слияния.

Вам не нужно переходить на новый рантайм, мигрировать на новый инструмент или запускать движок обмена сообщениями/памяти/оркестрации. Установка добавляет skill, набор hook-ов и бинарник `polywave-tools`. Skill и hook-и управляют рабочим процессом: они под капотом вызывают этот бинарник, так что при обычном использовании вы просто набираете `/polywave scout "feature"` и `/polywave wave`. CLI под рукой, когда он вам нужен (восстановление, скриптинг, CI, продвинутое использование), но большинство сессий никогда не обращаются к нему напрямую. Тяжеловесные агентные фреймворки требуют, чтобы вы переехали в их мир ради параллелизма; Polywave встречает вас в вашем и делает слияние безопасным.

> Опубликовано как [Agent Skill](https://agentskills.io) (открытый стандарт). Совместимо с Claude Code, Cursor, GitHub Copilot и другими инструментами, совместимыми с Agent Skills.

## Зачем

Вы уже запускали параллельных агентов. Вы знаете, что происходит: два агента редактируют один и тот же файл, слияние выдаёт мусор, и вы тратите на исправление больше времени, чем если бы сделали работу последовательно. Или ещё хуже: слияние проходит незаметно успешно, потому что оба агента правили разные функции в одном файле, но сделали противоречащие друг другу предположения об общем состоянии. Вы узнаёте об этом уже в рантайме.

Большинство фреймворков пытаются решить это лучшими промптами. Polywave решает это структурой:

- **Непересекающееся владение файлами.** Scout закрепляет каждый файл ровно за одним агентом ещё до того, как будет написан хоть один код. Два агента в одной волне не могут произвести правки одного и того же файла. Это закрепление принудительно применяется на границе инструментов, а не отдаётся на откуп дисциплине агента; нарушения становятся невозможными. Конфликты слияния становятся структурно невозможными.
- **Изоляция через worktree для каждого агента.** Каждый агент работает в собственном git worktree — отдельном каталоге с независимым деревом файлов. Параллельные сборки, тесты и записи в кэш инструментов не соревнуются за общее состояние.
- **Человеческое ревью перед выполнением.** Вы видите полный план (закрепление файлов, интерфейсные контракты, структуру волн) и утверждаете его до запуска хоть одного агента. Это последняя точка, где менять архитектуру дёшево.
- **Барьер пригодности.** Polywave говорит «нет», когда работа не раскладывается чисто. Оценка «не подходит» предотвращает превращение плохих декомпозиций в дорогостоящие провалы.

Polywave — это не агентный рантайм. Он не маршрутизирует задачи, не управляет обменом сообщениями между агентами и не хранит память между сессиями. Это протокол координации: безопасно разбить работу, проверить разбиение, запустить агентов независимо, слить детерминированно. Агенты работают параллельно, но не общаются друг с другом; корректность обеспечивается разбиением, а не сотрудничеством.

Это осознанно выбранная весовая категория. Полноценные агентные движки (Hermes, swarm-фреймворки и им подобные) объединяют рантайм выполнения, память, обмен сообщениями и оркестрацию в платформу, на которую вы переходите. Polywave не несёт ничего из этого. Он работает поверх того агентного рантайма, который у вас уже есть, и добавляет ровно одну вещь, которой этим платформам недостаёт: разбиение владения файлами и детерминированное слияние, делающие параллельные правки безопасными. Если вам нужен целый агентный движок — используйте его. Если вы хотите, чтобы ваш существующий CLI запускал несколько кодирующих агентов сразу, не взрывая слияние, — именно для этого и нужен Polywave.

В системе семь [ролей участников](https://github.com/blackwell-systems/polywave-protocol/blob/main/participants.md), но вы взаимодействуете с двумя: **Orchestrator** (ваша сессия Claude Code, координирует всё) и **Scout** (анализирует кодовую базу, закрепляет файлы, пишет план). Остальные пять (Scaffold Agent, Wave Agents, Integration Agent, Critic Agent, Planner) запускаются автоматически по мере необходимости.

## Как

**Что происходит, когда вы запускаете Polywave:**

1. Вы запускаете `/polywave scout "feature"` -> Scout анализирует кодовую базу, закрепляет файлы за агентами
2. Scout пишет IMPL-документ (YAML-артефакт координации, который определяет владение файлами, интерфейсные контракты и структуру волн) -> Вы ревьюите структуру волн
3. Вы запускаете `/polywave wave` -> Scaffold Agent создаёт файлы-заготовки, если нужно
4. Wave Agents запускаются параллельно -> Каждый работает в изолированном worktree над непересекающимися файлами
5. Orchestrator сливает -> Запускает тесты -> Убирает worktree-ы

**Ключевые механизмы:**

- **Orchestrator:** Синхронный координирующий агент в вашей сессии. Запускает агентов, обеспечивает соблюдение владения файлами, выполняет процедуру слияния, запускает барьеры верификации.

- **Scout:** Асинхронный агент. Анализирует кодовую базу, производит IMPL-документ с графом зависимостей, интерфейсными контрактами, таблицей владения файлами и структурой волн. Каждый файл закреплён ровно за одним агентом.

- **Scaffold Agent:** Запускается один раз перед Wave 1, если нужны общие типы. Создаёт файлы общих типов из контрактов IMPL-документа, проверяет компиляцию, коммитит в HEAD.

- **Wave Agents:** Асинхронные агенты, работающие параллельно. Каждый владеет непересекающимися файлами, реализует их по замороженным интерфейсным контрактам, проходит барьер верификации, коммитит работу, пишет отчёт о завершении.

- **Integration Agent:** Запускается после слияния волны. Подключает новые экспорты от wave-агентов к вызывающему коду. Не фатален; если подключение не удаётся, пробелы сообщаются человеку.

В протоколе есть встроенный **барьер пригодности**, который отвечает на [пять вопросов](https://github.com/blackwell-systems/polywave-protocol/blob/main/preconditions.md) до того, как будут произведены какие-либо промпты для агентов. Если предусловия не выполняются, scout выдаёт NOT SUITABLE и останавливается.

## Быстрый старт

**Требования:** Git 2.20+, jq 1.6+, Claude Code. Настоятельно рекомендуется языковой сервер для вашего стека (например, `gopls`, `rust-analyzer`, `pyright`, `typescript-language-server`): агенты используют LSP для навигации и без него откатываются к более медленному grep. Вам не нужны polywave-protocol или polywave-web.

```bash
# 1. Install skill files, hooks, and Agent permission
git clone https://github.com/blackwell-systems/polywave.git ~/code/polywave
~/code/polywave/install.sh    # configures Agent permission, symlinks skills, installs hooks

# 2. Install polywave-tools CLI (Homebrew — recommended)
brew install blackwell-systems/tap/polywave-tools

# 3. Initialize your project
cd your-project
polywave-tools init            # auto-detects language, build, and test commands

# 4. Verify
polywave-tools verify-install  # checks CLI, git, LSP, skill files, hooks, permissions
```

<details>
<summary>Alternative CLI install methods</summary>

**Готовый бинарник** (без Go-тулчейна): скачайте из [последнего релиза](https://github.com/blackwell-systems/polywave-go/releases/latest) и переместите его в свой `PATH`.

**Go install:**
```bash
go install github.com/blackwell-systems/polywave-go/cmd/polywave-tools@latest
```
Примечание: `go install` кладёт бинарник в `$(go env GOPATH)/bin` (обычно `~/go/bin`). Если после этого `polywave-tools` сообщает «command not found», значит, этот каталог не в вашем `PATH` — добавьте его:
```bash
echo 'export PATH="$(go env GOPATH)/bin:$PATH"' >> ~/.zshrc && source ~/.zshrc
```
Бинарники, установленные таким способом, сообщают свою версию как `dev`; для сборки с версией используйте Homebrew или релизный бинарник.
</details>

**5. Перезапустите Claude Code**, затем запустите свой первый scout:

```bash
/polywave scout "add a caching layer to the API client"
```

**Подкоманды:**

| Command | Purpose |
|---------|---------|
| `/polywave scout "<feature>"` | Проанализировать кодовую базу, произвести IMPL-документ |
| `/polywave wave` | Выполнить следующую ожидающую волну |
| `/polywave wave --auto` | Выполнить все оставшиеся волны без присмотра |
| `/polywave auto "<feature>"` | Scout + подтверждение + wave одной командой |
| `/polywave status` | Показать текущую волну и прогресс агентов |
| `/polywave bootstrap "<project>"` | Спроектировать структуру нового проекта с нуля |
| `/polywave interview "<description>"` | Структурированный сбор требований |
| `/polywave program --impl <slug> ...` | Собрать поставленные в очередь IMPL-ы в параллельную программу |
| `/polywave program plan/execute/status/replan` | Планирование по нескольким фичам и выполнение с гейтами по ярусам |
| `/polywave amend --add-wave/--redirect-agent/--extend-scope` | Изменить активный IMPL |

## Когда это использовать

Polywave окупается, когда у работы есть чёткие файловые швы, интерфейсы можно определить до начала реализации, и каждый агент владеет достаточным объёмом работы, чтобы оправдать параллельный запуск. Если цикл сборки/тестов превышает 30 секунд, это ещё сильнее увеличивает экономию.

Если работа не раскладывается чисто, Scout так и скажет. Он сначала прогоняет барьер пригодности и выдаёт NOT SUITABLE, вместо того чтобы навязывать плохую декомпозицию.

## Как работает параллельная безопасность

Polywave обеспечивает соблюдение двух независимых ограничений, которые вместе делают параллельное выполнение корректным:

**Непересекающееся владение файлами** предотвращает конфликты слияния. Каждый файл, который будет изменён, закреплён ровно за одним агентом в IMPL-документе. Два агента в одной волне не могут произвести правки одного и того же файла, поэтому шаг слияния всегда бесконфликтен.

**Изоляция через worktree** предотвращает интерференцию во время выполнения. Каждый агент работает в собственном git worktree — отдельном каталоге, который разделяет ту же git-историю, но имеет независимое дерево файлов. Параллельные сборки, тесты и записи в кэш инструментов не соревнуются за общее состояние.

Ни одно из ограничений не заменяет другое. Непересекающееся владение без worktree-ов: слияние безопасно, но параллельные сборки нестабильны. Worktree-ы без непересекающегося владения: выполнение чистое, но слияние даёт неразрешимые конфликты. Должны выполняться оба.

### Защита изоляции worktree (6 слоёв)

Агенты не всегда соблюдают инструкции об изоляции. Polywave рассматривает изоляцию worktree как инфраструктурную задачу, а не как задачу сотрудничества, с принудительным применением на основе hook-ов (E43) в качестве основного механизма.

| Layer | Mechanism | Type |
|-------|-----------|------|
| **E43** | **Принудительное применение на основе hook-ов**: hook-и жизненного цикла Claude Code (SubagentStart, PreToolUse:Bash, PreToolUse:Write/Edit, SubagentStop) автоматически внедряют переменные окружения, предваряют bash-вызовы командами cd и блокируют записи за пределами границ на границе инструментов. Нарушения становятся невозможными, а не просто обнаруживаемыми. | **Предотвращение (основное)** |
| 0 | **Pre-commit hook**: устанавливается автоматически командой `polywave-tools create-worktrees`. Блокирует коммиты в main во время активных волн. Orchestrator обходит его через `POLYWAVE_ALLOW_MAIN_COMMIT=1`. | Предотвращение |
| 1 | **Ручное предсоздание worktree-ов**: Orchestrator создаёт все worktree-ы до запуска хоть одного агента | Детерминированное |
| 2 | **Параметр `isolation: "worktree"`**: каждый запуск агента задаёт изоляцию worktree на уровне инструмента | На уровне инструмента |
| 3 | **Самопроверка Field 0**: агенты подтверждают ветку краткой проверкой (основное принудительное применение — это hook `validate_worktree_isolation` на SubagentStart) | Кооперативное |
| 4 | **Растяжка на этапе слияния**: Orchestrator подсчитывает коммиты в каждой ветке worktree перед слиянием. Ноль коммитов = сбой изоляции. Останавливается с вариантами восстановления. | Детерминированное |

## Polywave-Teams (Экспериментально)

[`docs/proposals/polywave-teams/`](../../docs/proposals/polywave-teams/) — альтернативный слой выполнения на основе Claude Code Agent Teams. Тот же протокол, тот же IMPL-документ, тот же Scout. Другая обвязка волн: члены команды заменяют фоновые вызовы инструмента Agent, обеспечивая обмен сообщениями между агентами и оповещения об отклонениях в реальном времени.
